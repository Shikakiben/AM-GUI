# Translations (i18n)

This folder contains the AM-GUI interface translations.

## Structure

```
src/i18n/
  locales/            ← source of truth (one JSON file per language)
    en.json           ← reference language (all keys)
    fr.json
    vi.json
    ...
  translations.js     ← GENERATED by build-i18n.js — do not edit by hand
  build-i18n.js       ← generator (node src/i18n/build-i18n.js)
  normalize-i18n.js   ← optional tool: reorders keys to match en.json (maintenance)
  README.md
```

## Add or fix a translation

1. Edit the matching `locales/<lang>.json` file (or create it for a new language).
2. Regenerate the runtime file:
   ```sh
   npm run build:i18n
   ```
   (`npm start` and `npm run dist` do this automatically.)

## Add a new language

1. Copy `en.json` to `locales/<code>.json` (e.g. `de.json`) and translate all the values.
2. Add the new language's name (`settings.<code>`) in **all** JSON files:
   - in `de.json` → `"settings.de": "Deutsch"` (native name)
   - in `en.json` → `"settings.de": "German"`
   - in `fr.json` → `"settings.de": "Allemand"`
   - … in every existing language.
3. Run `npm run build:i18n`.

> The language list in the settings panel is generated automatically from the JSON files
> (`buildLanguageOptions()` in `renderer.js`): nothing to change in `index.html`.

> ℹ️ JSON does not support comments: all documentation lives in this README.
> The `test/main/i18n.test.js` test rejects in CI any incomplete language (missing key) or
> any key present in a language but not in `en.json`.

## Format of a language file

Each JSON file contains **4 sections**:

```json
{
  "ui": {
    "tabs.all": "Applications",
    "tabs.installed": "Installed"
  },
  "tray": {
    "open": "Open AM-GUI",
    "quit": "Quit"
  },
  "contextMenu": {
    "undo": "Undo",
    "copy": "Copy"
  },
  "errors": {
    "errNoPm": "No package manager found"
  }
}
```

- **`ui`** : all interface texts (tabs, buttons, toasts, settings…).
- **`tray`** : system tray menu labels (`open`, `quit`).
- **`contextMenu`** : context menu (cut/copy/paste…).
- **`errors`** : main-process error messages (used via `tErr`).

## Important rules

- **`en.json` is the reference** : any new key must first be added there.
- **Every language must contain exactly the same keys** as `en.json`. The
  `test/main/i18n.test.js` test rejects an incomplete language in CI.
- Variables use the `{name}` format (e.g. `"updates.duration": "({dur}s)"`).
- HTML is allowed only for a few flagged keys (e.g. `data-i18n-html`).
